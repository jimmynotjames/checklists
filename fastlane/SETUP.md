# Fastlane setup

This repo uses Homebrew fastlane, verified with 2.241.2. Run commands from the
repository root. Install on a new machine with
`brew install fastlane`. There is no Gemfile or plugin dependency. Supply a UTF-8
locale per command if your shell does not already have one:
`LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 fastlane lanes`. Routing: AGENTS.md §"Commit and PR
style".

## Credentials

Secret inventory and reconstruction: [`core-docs/secrets-list.md`](../core-docs/secrets-list.md).
`fastlane ios verify_auth` confirms read-only access to the Appfile's app and prints its App Store
Connect ID; it changes nothing.

Binary archives also need an Apple Distribution identity in the login keychain and automatic
signing for team `EDMB3Z5KAY`. `archive_validation` builds with the beta lane's options (so it can
update provisioning through the API key) plus the Release values `scripts/verify_release_secrets.sh`
checks, but never uploads, bumps the build number, or commits.

## English source and transcreated overrides

`metadata/` is the source of truth; there is no download lane. `metadata/en-US/` is
the American English source copy, and `metadata-locales.json` lists the metadata
locales the installed Fastlane version supports. Preparation resolves each field for
every locale from an explicit locale override when present, or from English otherwise.

The other storefront directories hold transcreated overrides for `subtitle`,
`keywords`, `description`, and `release_notes`. `name` and the URLs are copied
from English unchanged, except fields a storefront authors itself under
`PASSTHROUGH_OVERRIDES` in `scripts/translate_metadata/metadata_locales.py`. Everything
else is generated by the `appstore-translate-metadata` skill and never hand-authored; edit the English
source and re-run the skill. `python3 scripts/translate_metadata/check_metadata.py`
gates the set, and the `push_metadata` lane refuses to upload until it passes.

Which skill translates what: `core-docs/localization-spec.md §The four pipelines`.

## Publishing behavior

The beta lane uses scheme `checklists`, project
`checklists/checklists.xcodeproj`, and `scripts/verify_release_secrets.sh`. It
allocates `CURRENT_PROJECT_VERSION` for the explicit marketing version and writes
a recovery record under `tmp/releases/`. It commits the project-file bump only
after a successful TestFlight upload. Failed uploads retain their local recovery
state and are never retried automatically.

`python3 scripts/appstore_metadata.py prepare --output tmp/appstore-metadata`
builds a reviewable resolved metadata tree for every locale in
`fastlane/metadata-locales.json`. Blank present values are rejected; absent optional
fields stay omitted.

`fastlane ios push_metadata app_version:X.Y.Z` requires that exact editable iOS
version to already exist in App Store Connect. Create or select it manually first.
The lane does not create or rename a version, and changes no screenshots, binary,
submission state, availability, pricing, or phased-release setting.

Automatic submission remains out of scope. The user manually attaches the tested TestFlight build
and submits the release in App Store Connect.

## Screenshot content and capture

`fastlane/screenshot-config.json` holds the runtime/storefront locale mappings, the
devices, and the shots; the Python pipelines derive from it. Each active locale's seed
catalog is generated, and `make gate` fails when one drifts from the string catalog:
`core-docs/localization-spec.md §Screenshot seeds`.

A full capture is release-time work and runs serially: about a minute per locale per
device once the build is warm. It captures every
locale on one device, shuts that simulator down, then moves to the next. It is resumable by
`run_id`, and `locales:` takes a subset of runtime codes for a spot check.

The devices are the 6.9" iPhone and iPhone Duo's outer display, which deliver uploads as
`APP_IPHONE_DUO`. The Duo simulator boots folded, and neither `simctl` nor XCTest
can unfold it, so the inner display is not captured; the size check rejects a capture of the
wrong display.

The English seed mirrors the shipped sample data but checks some items, so the home
screen shows progress. Screenshot launches use Debug-only, disposable in-memory stores
and never import or sync user data; settings start opted out of analytics so first-run
consent cannot cover a strict-region capture. The capture test is excluded from normal
UI-test runs and shoots the real UI, with no frames or generated artwork.

Validate content with `python3 scripts/screenshot_content/check_content.py` and
capture with `fastlane ios screenshots`. Local capture does not authenticate
with App Store Connect. Preserve its run ID and review the generated PNGs before
publication; the run's validation rejects missing, malformed, or stale images.

Runs live under `.build/screenshots/runs/RUN_ID/`: `raw/` (runtime-coded captures),
`storefront/` (validated upload files), `review.html`, `capture-report.json` (hashes and
dimensions), build logs, and the private Snapshot cache. The reusable build cache is
`.build/screenshots/DerivedData`; a per-checkout lock allows one capture at a time.

```bash
python3 scripts/screenshot_content/capture_progress.py status --run-id RUN_ID
fastlane ios screenshots run_id:RUN_ID locales:en-US
```

The second command resumes only that run's pending targets. Omit `run_id` for a fresh
run, which changed source, seeds, or configuration require. `Snapfile` rejects direct
`fastlane snapshot`.

## Screenshot publication

`fastlane ios inspect_screenshots` is read-only: it reports the primary locale
and screenshot sets on the editable version, falling back to the live version
when none is editable.

Apple defaults new localizations to primary-language screenshots, but existing
explicit sets take precedence, so inspect before relying on fallback. See [Apple's localization guidance](https://developer.apple.com/help/app-store-connect/manage-app-information/localize-app-information/)
and [screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/).

Screenshot publication requires a reviewed run and an explicit existing editable
version:

```bash
fastlane ios push_screenshots app_version:X.Y.Z run_id:REVIEWED_RUN
# Optional subset retry: add locales:en-US (runtime codes; enabled locales only).
```

It replaces the selected active locales' screenshot sets, old display sizes included, so
the large iPhone shots serve smaller sizes, and touches nothing else: no binary, text
metadata, version, availability, or submission. To test the infrastructure, use the mocked
publishing tests and local captures, never an upload.
